# Этапы разработки и точки коммита

Коммит фиксирует реально законченный результат. Даты не подменяем,
готовый код задним числом не раскладываем по искусственной истории.
Несколько небольших коммитов в день допустимы; для этого проекта удобнее
завершать по одному крупному этапу за рабочую сессию.

| Этап | Законченный результат | Предлагаемое сообщение коммита |
| --- | --- | --- |
| 1 | Архитектура, требования, выбор поста USGS, конфигурация, загрузчики USGS и Open-Meteo, единый формат гидроданных, контроль качества, признаки, baseline, автономный демонстрационный запуск и тесты | `feat: establish reproducible river forecasting foundation` |
| 2 | Срочные показания USGS continuous и их агрегация, PostgreSQL, инкрементальная загрузка с учётом исправлений и журнал | `feat: ingest USGS gauge observations into PostgreSQL` |
| 3 | EDA на реальных данных, пропуски и аномалии, сезонность, вклад осадков и расхода, признаки и абляции | `feat: analyze river history and build causal features` |
| 4 | Ridge и XGBoost, rolling-origin, baseline на тех же датах, финальный holdout, MLflow и подбор параметров | `feat: compare forecasting models with temporal validation` |
| 5 | Prefect, обновления по расписанию, воспроизводимое обучение и повторный запуск после сбоя | `feat: orchestrate ingestion and forecasting workflows` |
| 6 | Streamlit с фактом, прогнозом, качеством и свежестью данных | `feat: add river monitoring and forecast dashboard` |
| 7 | Выбранные дополнительные компоненты, интеграционная проверка, отчёт и презентация | `feat: finalize experiment analysis and project deliverables` |

После каждого этапа: проверить запуск по README, прогнать необходимые
проверки, просмотреть `git diff`, убрать локальные данные и секреты,
зафиксировать результат. Следующий этап начинаем отдельной сессией.

Первый этап не закрывает весь проект. Подключение PostgreSQL, Prefect,
MLflow, XGBoost и Streamlit выполняется по мере появления соответствующего
функционала, без неработающих заготовок в коде.
