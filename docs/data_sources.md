# Источники: USGS и Open-Meteo

Проверено 1 ноября 2026 года. Используются источники исходной аннотации.
Для USGS выбрана река в США, где доступны уровень, расход и их история.

## Гидропост

**Suwannee River at Branford, Florida — USGS 02320500.**
[Официальная карточка](https://waterdata.usgs.gov/monitoring-location/USGS-02320500/).

- Идентификатор API: `USGS-02320500`; код TOML: `"02320500"`.
- Координаты: `29.955785012958, -82.9276277589354`.
- Уровень: `00065`, исходные единицы `ft`.
- Расход: `00060`, исходные единицы `ft^3/s`.
- Статистика обоих параметров: `00003`, суточное среднее.
- Полный ответ каталога сохраняется с текущими метаданными поста.

Для ранее проверенных постов на Потомаке и Rappahannock тестовые запросы
не вернули суточного среднего уровня. Для Suwannee на постах White Springs
и Branford такие значения получены. Выбран Branford: проверены обе нужные
характеристики и свежие суточные уровни за 19–25 октября 2026 года.
Это проверка конкретных параметров API, а не отсутствия любых наблюдений
на остальных реках.

## Интерфейс

Используется **USGS Water Data API v1** — современный интерфейс того же
источника USGS. [Документация перехода](https://api.waterdata.usgs.gov/docs/ogcapi/migration/).
Старый WaterServices не используется.

```text
GET https://api.waterdata.usgs.gov/ogcapi/v1/collections/monitoring-locations/items
  f=json
  monitoring_location_number=02320500
  limit=2

GET https://api.waterdata.usgs.gov/ogcapi/v1/collections/daily/items
  f=csv
  monitoring_location_id=USGS-02320500
  parameter_code=00065   (отдельный запрос для 00060)
  statistic_id=00003
  time=2008-01-01/2023-12-31
  limit=10000
  sortby=time
```

Интервал одного запроса ограничен 9 000 днями на один параметр, чтобы одна
суточная серия не достигала лимита в 10 000 строк. Если ответ достигает
лимита, содержит разные серии или повторные даты, загрузка останавливается:
усечённая история не принимается как полная. Пропуски допустимы и учитываются.

Ключ из `USGS_API_KEY` передаётся заголовком `X-Api-Key` только USGS.
Он не включается в URL, TOML или снимки.
[Описание ключей и ограничений](https://api.waterdata.usgs.gov/docs/ogcapi/keys/).

## Единицы и происхождение

| Исходная величина | Нормализованная | Пересчёт |
| --- | --- | --- |
| Gage height, ft | `level_cm` | × 30.48 |
| Discharge, ft³/s | `discharge_m3s` | × 0.028316846592 |

Gage height относится к шкале поста. Высота места из каталога не прибавляется
к нему: она не доказывает историческую высотную привязку каждого наблюдения.
Для абсолютных высот нужна отдельная проверка изменений нуля и системы высот.
В проекте прогнозируется уровень по шкале USGS.

Сохраняются `time_series_id`, `approval_status`, `qualifier` и
`last_modified` отдельно для уровня и расхода. Клиент не усредняет разные
серии и не принимает максимум вместо среднего. Предварительные значения
`Provisional` сохраняются со статусом; пропуски не заменяются нулём.

## Погода и время

[Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api):
модель `era5`, суточные температура, осадки, влажность, формат JSON.
Это реанализ, а не сохранённый прогноз погоды, выпущенный в прошлом.

Для объединения выбран фиксированный EST (UTC−5, `Etc/GMT+5`).
Даты суточных USGS используются как предоставленные API. Использование
местного стандартного времени для гидрологических суток обсуждается в
разделе 2.3.1 [CAMELS-SPAT](https://hess.copernicus.org/articles/29/5791/2025/).
Перед оперативным выпуском нужно проверить границы суток и сроки
публикации конкретных рядов.

   измерений и покрытия суток. Импорт готовых суточных средних сам по себе
   ещё не закрывает обработку слабоструктурированных данных из задания.
2. Сопоставить собственные агрегаты с `daily`, учитывая временные интервалы,
   пропуски и различие среднего по отсчётам и среднего по времени.
3. Реализовать инкрементальность с учётом исправлений `last_modified`.
4. Учесть доступность данных на момент выпуска: исправленная история
   не является архивом первоначальных публикаций.
5. Добавить погодные точки по водосбору и при необходимости вышележащие
   посты, оценив пользу по временной валидации.
