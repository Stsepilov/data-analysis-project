# Прогнозирование уровня воды в реке

Учебный проект по дисциплине «Интеллектуальный анализ данных».
Цель — объединить гидрологические наблюдения и погоду, прогнозировать
уровень на сутки вперёд и показывать результат вместе с оценкой качества.

**Текущий этап: основа проекта и persistence baseline.** Выбран пост
**USGS 02320500 — Suwannee River at Branford, Florida, США**.
Источники соответствуют аннотации: **USGS Water Data API и Open-Meteo API**.
[Карточка поста](https://waterdata.usgs.gov/monitoring-location/USGS-02320500/).

## Что реализовано

- Конфигурация поста и периода в TOML.
- Загрузка суточных средних уровня и расхода воды через USGS Water Data API v1.
- Погода Open-Meteo ERA5: температура, осадки и влажность.
- Разные форматы: гидрология в CSV, погода в JSON; каталог постов в GeoJSON.
- Исходные снимки с SHA-256 и параметрами получения.
- Проверка поста, параметров, статистики, единиц, дат, дублей и пропусков.
- Перевод уровня из футов в сантиметры, расхода — из ft³/s в м³/s.
- Дневная таблица, лаговые, оконные и календарные признаки.
- Наивный прогноз «завтра как сегодня», MAE и RMSE в сантиметрах.
- Автономная демонстрация на синтетических данных, журнал запусков и тесты.
- Конфигурация GitHub Actions для проверки после публикации репозитория.

PostgreSQL, Ridge/XGBoost, MLflow, Prefect и Streamlit вводятся следующими
этапами. Подробности — [требования](docs/requirements.md) и [план](docs/roadmap.md).

## Установка и первый запуск

Нужны Python 3.12 или 3.13 и [uv](https://docs.astral.sh/uv/).
Команды выполняются из корня репозитория. Активация окружения не нужна.

```powershell
uv sync --locked
uv run --locked river-forecast demo
uv run --locked pytest
uv run --locked ruff check .
uv run --locked ruff format --check .
```

Демонстрация после установки работает без сети. Результаты находятся в
`data/processed/demo/` и `artifacts/demo/`; они исключены из Git.
Метрики на синтетике проверяют код, а не качество на реальной реке.

## Реальные данные

```powershell
uv run --locked river-forecast fetch --config config/suwannee_branford.toml
uv run --locked river-forecast evaluate --config config/suwannee_branford.toml
```

Это конфигурация по умолчанию: `--config` можно опустить.
Первая команда проверяет пост и координаты, получает уровень (`00065`) и
расход (`00060`) со статистикой суточного среднего (`00003`), затем погоду.
Сырые ответы сохраняются в `data/raw/usgs/` и `data/raw/weather/`.
В `data/processed/suwannee_branford/` появляются `hydrology.csv`,
`weather.csv`, `daily.csv` и метаданные. Вторая команда считает baseline,
сохраняет признаки и артефакты в `artifacts/suwannee_branford/`.
Журнал всех запусков — `artifacts/runs.jsonl`.

Проверенный период 2008–2023: 5 844 календарных дня, 107 пропусков уровня,
один пропуск расхода. Целевой уровень не интерполируется. Свежие суточные
уровни того же поста проверены за октябрь 2026 года; запуск по расписанию
относится к следующему этапу. При сетевой ошибке процесс завершается
с ошибкой и записью в журнале, без подстановки синтетических данных.

Для регулярных загрузок можно получить бесплатный
[ключ USGS](https://api.waterdata.usgs.gov/signup/) и задать его в окружении:

```powershell
$env:USGS_API_KEY = "ваш_ключ"
uv run --locked river-forecast fetch
```

Ключ необязателен для небольшого числа запросов. Он отправляется только
USGS заголовком `X-Api-Key`, не попадает в URL, TOML или снимки. Файлы
`.env` автоматически не читаются.
[Документация ключей и лимитов](https://api.waterdata.usgs.gov/docs/ogcapi/keys/).

Чтобы сменить пост, скопируйте TOML и задайте код **строкой с ведущими нулями**,
координаты, часовой пояс и период. Имя TOML определяет папку результата.
Нужны оба параметра с суточной статистикой `00003`: она есть не у всех постов.
Загрузка пока полная; инкрементальность и PostgreSQL — этап 2.

## Методика

Цель — **суточный средний уровень следующего дня относительно шкалы поста**.
Уровень не равен расходу, глубине или абсолютной высоте над морем.
Используется одна временная серия каждого параметра; неоднозначность,
несовпадение единиц или другая статистика останавливают загрузку.

Признаки для даты `t` используют известный уровень `t` и его прошлые значения.
Погодные признаки доступны не позднее `t−5`: это исходное допущение о
задержке реанализа, а не доказательство доступности всех исправленных
исторических значений в момент прогноза. Будущая фактическая погода
в признаки не входит. Погода группируется по фиксированному EST
(`Etc/GMT+5`, UTC−5), чтобы смена летнего времени при повторном запросе
не меняла границы погодных суток. Одна точка пока не описывает весь водосбор.

2023 год исключён из текущих метрик и зарезервирован для финальной проверки.
Baseline оценивается на последних 20% календарных дат периода разработки
2008–2022, то есть в 2020–2022. Прогнозы одношаговые; перед каждым доступно
новое наблюдение. Неполные пары исключаются с подсчётом.
На 994 пригодных парах MAE = **5.83 см**, RMSE = **8.33 см**.

Детали: [источники](docs/data_sources.md), [архитектура](docs/architecture.md),
[протокол baseline](docs/experiments/001_baseline.md).
Единая валидация трёх моделей появится на этапе моделирования.

## Структура

```text
config/                 пост и параметры эксперимента
src/river_forecast/      загрузка, проверки, признаки, baseline, CLI
tests/                  проверки без внешних сервисов
docs/                   требования, источники, архитектура, этапы
data/raw/               исходные снимки (локально)
data/processed/         дневные таблицы и признаки (локально)
artifacts/              метрики, прогнозы, сведения о запуске (локально)
.github/workflows/      автоматические проверки
```
